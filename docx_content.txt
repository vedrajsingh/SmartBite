1.5  Animation Guidelines
Page load
Staggered fade-up for hero elements: H1 at 0ms, subtext at 150ms, CTAs at 280ms, stats at 400ms
Scroll reveal
Elements fade-up 20px as they enter viewport. Use Intersection Observer API.
Card hover
translateY(-4px) + box-shadow deepening. 200ms ease-out.
Button hover
scale(1.02) + brightness(1.05). 180ms ease.
Chat messages
Slide-in from bottom-left. AI thinking: 3-dot bounce animation.
Correct answer
Green flash (#1D9E75) + XP counter counts up with bounce. 400ms.
Wrong answer
Red shake animation (300ms). Hint prompt fades in below.
Level complete
Full-screen confetti (canvas-confetti) + score count-up + streak fire emoji.
Transition rule
All UI feedback ≤ 300ms. Page transitions ≤ 500ms. Nothing longer.
3D mouse tracking
hero orb tracks mouse at 20% of cursor movement. requestAnimationFrame.

4.4  Adaptive Learning Loop (Core AI Logic)
  ★ This is the single most important UX behavior. Fully automatic — student never has to choose format or make decisions.
Step
What Happens
Implementation Detail
1 — Upload
Student uploads any material in any format
Same upload zone UI. Any format accepted.
2 — AI Auto-Converts
AI reads and AUTOMATICALLY picks best format: MCQ, fill-blank, flashcard, match-pairs
No user selection ever. AI decides based on content type.
3 — Challenge Starts
Questions are level-based: easy → medium → hard. Instant feedback after each.
3D card flip animation on each new question.
4 — AI Analyzes
After challenge: AI records which questions wrong, which concepts weak
Stored in DB: question_id, user_id, attempt_count, correct_bool
5A — Mistakes Found
Auto-generates NEW challenge targeting only the wrong concepts. No user input.
Seamless transition. Buddy chat message prepares student.
5B — All Correct
AI asks: 'Next topic pe jaayein? Ya isi topic ko aur deep karte hain?'
Two clear buttons: Next Topic / Go Deeper
6 — Loop Continues
Cycle repeats until student exits. Each session builds on previous.
Progress saved. Resume from same point on next login.

10.3  AI Processing Pipeline (Step-by-Step)
  ★ Target: < 30 seconds end-to-end for a standard 20-page PDF. All steps run on BullMQ worker, NOT on the API server.
Step
What Happens
Technical Detail
1 — Upload
Client POSTs file → Express multipart handler → validate MIME + magic bytes → upload to S3 → create study_materials row (status: queued) → return material_id to client
Max 50MB. Reject executables. Signed S3 upload URL for large files.
2 — Queue
Worker picks up material_id from BullMQ 'ai-processing' queue. Update status: processing.
Redis-backed BullMQ. Priority queue for Pro+ users.
3 — Extract Text
PDF: pdf-parse library. DOCX: mammoth.js. Image/scan: Tesseract.js OCR (English + Hindi). Plain text: direct.
Fallback chain: if pdf-parse fails → render page as image → OCR.
4 — Analyze
GPT-4o prompt: 'Extract topics, identify content type (conceptual/factual/procedural), detect subject area.' Returns: {topics[], contentType, subject, difficulty}.
System prompt enforces JSON-only output. Parse + validate with Zod.
5 — Generate
GPT-4o prompt: 'Generate {n} questions for topic {X} in format {chosen by AI based on contentType}. Return JSON array: [{q, options, answer, explanation, topic, difficulty}].'
n = 5 per level. Max 10 levels. Total max 50 questions per material.
6 — Store
Save questions JSONB to games table. Update study_materials status: ready. Emit Socket.io event 'game:ready' to user's room.
Emit: {materialId, gameId, topicsCount, totalQuestions}
7 — Notify
Client receives WebSocket event → fetch game via GET /api/games/:materialId → render challenge UI.
Fallback: client polls GET /api/materials/:id/status every 3s if no Socket event.
Error handling
Worker catches extraction failures → retry 3x with 5s delay → mark status: failed → emit 'game:failed' event → user sees: 'Kuch gadbad ho gayi! Dobara try karo.'
Sentry captures error with full context.
Adaptive loop
After session: POST /api/sessions with results → backend identifies wrong question topics → generate new targeted game via same pipeline but with topic filter.
Only topics with wrong_count > 0 are targeted.
Wrong answer advice
Inline (fast): POST /api/ai/advice {questionText, userAnswer, correctAnswer, topic} → GPT-4o generates 2-sentence explanation → returned in < 2s.
Separate lightweight GPT call. Max 100 tokens output.

10.5  Security Architecture
Authentication
JWT access tokens: 15min expiry. Refresh tokens: 7 days. Both in httpOnly cookies. CSRF protection via SameSite=Strict.
Authorization
Role-based: student / mentor / admin. Resource-level: user can only access own materials, games, sessions. Supabase RLS enforces at DB level.
File upload safety
Validate MIME type + file magic bytes (first 4 bytes). Reject: .exe, .sh, .php, .js uploads. Quarantine zone in S3 before processing.
Rate limiting
Redis-backed rate limiter (express-rate-limit + ioredis): 100 req/min/IP general · 20 AI req/min/user · 10 uploads/hr/free user.
SQL injection
All queries via Prisma ORM parameterized statements. No raw SQL strings.
XSS prevention
DOMPurify on all user-generated content before render. Content-Security-Policy headers set.
CORS
Whitelist: yourbuddy.in · app.yourbuddy.in · localhost:3000 (dev only). Reject all others.
HTTPS
Enforced everywhere via Cloudflare. HTTP → 301 redirect to HTTPS. HSTS header: max-age=31536000.
API key safety
No API keys on frontend. All OpenAI/Claude calls via backend only. Keys in environment variables. Rotated quarterly.
Data residency
All user data, S3 buckets, PostgreSQL: AWS ap-south-1 (Mumbai). DPDP Act 2023 compliant.
Dependency scanning
GitHub Dependabot + npm audit in CI/CD. Critical CVEs block deployment.
Penetration testing
Annual pentest before major releases. OWASP Top 10 checklist before launch.
